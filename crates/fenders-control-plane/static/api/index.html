Fenders API

Create projects, deploy WASM and explicitly invoke commands through the Fenders control plane.

Base path: /v1. OpenAPI contract.

Not available: pause and resume. Requests that ask for them are answered 501 with code not_available.

Access

A workspace owner or the operator creates a key (POST /v1/workspaces/{workspace}/api-keys). Choose a project, permissions and expiry. Save the secret when it is displayed: Fenders stores only its hash. Send Authorization: Bearer <key> over HTTPS. Never place a key in a URL.

Keys belong to the workspace, not the creator's login. Revocation and expiration prevent new authorization; work already admitted can continue. Keys cannot create other keys, manage members, provision workspaces or change allowances.

PermissionAllows
readScoped apps, metadata, logs, operations and usage. Secret values are never readable.
apps:writeUpload, deploy, attach versions, activate releases, start/stop, configure triggers and app connections.
runs:writeExplicitly invoke an existing command.
projects:writeCreate projects; requires workspace-wide scope.
connections:writeRegister/revoke external HTTPS or TCP destinations.
secrets:writeCreate encrypted secrets.

Deployment access is powerful: it can change code, attach permitted destinations and enable HTTP or scheduled execution. A Runner is useful when automation should only invoke already configured commands.

First command

Use GET /v1/me and GET /v1/workspaces to discover your scope. Create a project with a workspace-wide key, or select one from GET /v1/workspaces/{workspace}/projects.

# Set FENDERS_API_KEY securely in your environment.
API=https://fenders.example.com/v1
curl -sS "$API/workspaces" -H "Authorization: Bearer $FENDERS_API_KEY"

curl -sS "$API/workspaces/$WORKSPACE/projects" \
  -H "Authorization: Bearer $FENDERS_API_KEY" \
  -H 'Content-Type: application/json' -H 'Idempotency-Key: create-my-project' \
  -d '{"name":"My project"}'

BASE="$API/workspaces/$WORKSPACE/projects/$PROJECT"
curl -sS "$BASE/artifacts" -H "Authorization: Bearer $FENDERS_API_KEY" \
  -H 'Content-Type: application/wasm' --data-binary @app.wasm

curl -sS "$BASE/artifacts/$ARTIFACT/inspection" \
  -H "Authorization: Bearer $FENDERS_API_KEY"

Upload accepts a WASI component (maximum 16 MiB). Poll inspection until validation completes; check its supported entry points before choosing triggers. Uploading identical bytes within the project reuses the artifact.

curl -sS "$BASE/apps/deploy" -H "Authorization: Bearer $FENDERS_API_KEY" \
  -H 'Content-Type: application/json' -H 'Idempotency-Key: deploy-first-version' \
  -d '{"name":"hello","artifact_id":"ARTIFACT_ID", "triggers":{"manual":true,"http":false}}'

# The operation's resource_id is the app ID. Deployment does not run the command.
curl -sS "$BASE/apps/$APP" -H "Authorization: Bearer $FENDERS_API_KEY"

# Explicit invocation; keep this key for every retry of this particular run.
curl -sS "$BASE/apps/$APP/runs" -H "Authorization: Bearer $FENDERS_API_KEY" \
  -H 'Content-Type: application/json' -H 'Idempotency-Key: run-order-123' -d '{}'

# This operation's resource_id is the run ID.
curl -sS "$BASE/apps/$APP/runs/$RUN" -H "Authorization: Bearer $FENDERS_API_KEY"
curl -sS "$BASE/apps/$APP/logs?run_id=$RUN" -H "Authorization: Bearer $FENDERS_API_KEY"

Retries and outcomes

Send a unique Idempotency-Key (1–128 characters) for each mutation, except content-addressed artifact uploads and read-only validation/preview. Retry the same method, path and body with the same key after a lost response. A changed body with a reused key returns 409. Keys are scoped to the workspace for project/key/secret creation, and to the project for app/connection operations.

App and connection mutations return an operation with id, kind, resource_id and state. A successful operation is not proof of execution: follow the app/run and its observed state. An unknown command outcome remains unknown and is never automatically replayed. A new key for a run means a new execution request.

Key creation returns the secret only in the first response. Retrying returns the original metadata without a secret. If that first response is lost, revoke the key and create a replacement.

Version activation, lifecycle, connections and trigger edits require expected_revision. Use the app's revision, except trigger edits use the revision from GET /apps/{app}/triggers. On a conflict, reread and review before submitting a new intent.

Responses

Lists with history return items and next. Pass next as before for apps, versions, runs, releases and events; logs use after. Keep filters unchanged while following a cursor. Small catalogs currently return arrays; see each response in OpenAPI.

Errors contain error (human-readable message), code and request_id. Every management response includes X-Request-Id. 400 means invalid input, 401 invalid/expired/revoked credentials, 403 missing permission, 404 missing or inaccessible resource, 409 conflict, 413 oversized input, and 503 temporarily unavailable. Do not parse human-readable messages.

This is the workspace API, for a workspace API key. The operator calls a host product makes (workspaces, nodes, keys) are described in docs/EMBEDDING-API.md of the source repository; internal node protocols are outside this contract.
